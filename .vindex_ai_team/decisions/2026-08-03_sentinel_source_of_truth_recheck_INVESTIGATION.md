# Sentinel Phase 4 — Source of Truth Recheck (broader sweep beyond Nexus's 2 fixes)

**Scope**: read-only. Confirms whether any source-of-truth violation survives beyond the two Project
Nexus already fixed and committed tonight (`routers/ccc.py`'s `_compute_health`, `routers/zadaci.py`'s
independent missing-document detector). No code changed by this investigation.

**Method**: grepped `health_score`, `nedostajuci_dokazi`/`nedostajuci_count`, `rizik`,
`calculate_procesni_rizik`, `identify_case_problems`, `case_dna`/`snaga_predmeta`, `strategy`/`zakljuc`,
audit-table inserts (`predmet_istorija`, `audit_log`), and independent `_compute_*`/`calculate_*`
function definitions across `routers/` and `services/`. Every candidate hit was opened and read in full
(not just grep context) to determine whether it recomputes a fact/conclusion another module already
owns, or legitimately computes something different.

## FINDING 1 — HIGH — `routers/dashboard.py:327-451` (`matter_health_score`, endpoint `GET /api/predmeti/{predmet_id}/health`)

**What it is**: a THIRD independent "case health" scoring formula, alongside the canonical
`services/risk_engine.py::calculate_procesni_rizik` (0-100 `health_score`, now the single source used by
both `routers/matter_intel.py` and, since tonight's Nexus fix, `routers/ccc.py`).

**Why it's a genuine violation, not a false positive**: it answers the exact same question
("how healthy/at-risk is this case, 0-100") with a **different formula and different inputs**:
- Aktivnost (beleška/komentar in last 7 days): 0-25
- Risk level, read from a **free-text parse of the latest `[Rizik]` entry in `predmet_istorija`**
  (`nivo == "nizak"/"srednji"/else`): 0-25
- Critical deadlines in next 48h (not 7 days, unlike Risk Engine): 0-25
- Document count (raw count, no `tip_dokaza`/expected-doc-type matching at all — cruder than even
  ccc.py's pre-fix bug): 0-15
- Any future hearing scheduled: 0-10

None of this calls `calculate_procesni_rizik`. For the same case, this endpoint and
`matter_intel`/`ccc` can and will disagree on both the numeric score and the status tier
(`zdrav`/`upozorenje`/`kriticno` here vs. Risk Engine's own `nivo`), because the category weights,
lookback windows, and even the deadline urgency window (48h vs. 7 days) differ.

**Why this wasn't caught by Nexus's audit or flagged as Critical here**: it is **not currently wired to
the frontend**. Confirmed via `grep -rn "matter_health_score\|predmeti/.*\/health" static/*.js` — zero
matches (the only `/health`-shaped calls in `static/vindex.js` are `/api/apr/health`, `/api/portal/health`,
`/web3/health-score`, `/api/firm/health-index` — all unrelated endpoints). No lawyer sees this number
today.

**Why it's still HIGH, not Low**: it is fully alive — registered on the router, covered by 7+ passing
tests in `tests/test_dashboard.py`, and was itself the subject of a bug fix in the 2026-07-24 nightly
repair (`docs/NIGHTLY_REPAIR_REPORT_2026-07-24.md` item 7 — the `faktori.aktivnost` re-derivation bug).
That means it reads as production-ready, tested infrastructure to any future engineer (including a future
autonomous session) who might wire it into a UI panel or hand it to a mobile/API integration partner —
at which point it becomes a live, user-facing contradiction with zero warning, exactly the failure mode
this mission exists to prevent. A landmine is still a landmine before it's stepped on.

**Recommendation** (not yet implemented — flagging per this investigation's read-only scope): either (a)
delete the endpoint and its formula, or (b) make it a thin wrapper around
`calculate_procesni_rizik`/`identify_case_problems` like `ccc.py` now is. Given it's untested-by-usage and
has no frontend caller, deletion is the lower-risk option unless the founder confirms an external
consumer depends on it.

## Candidates checked and ruled out (confirmed NOT violations)

1. **`routers/strategija.py:323`** (`nedostajuci_dokazi` in the Strategy Engine's GPT JSON schema) —
   this is a *qualitative legal-strategy* judgment ("what evidence would strengthen our legal position,
   with `vaznost`/`nacin_pribavljanja`"), generated by Strategy Engine and owned by it per the ownership
   rule (Strategy Engine = pravni zaključci). It answers a different question than Risk Engine's
   deterministic "which expected document types are missing" checklist. Confirmed by reading the full
   GPT schema context — not a recomputation of the same fact.

2. **`services/case_pipeline.py:88` (`calculate_case_ready_score`)** — a *setup-completeness checklist*
   ("is this case fully set up": has docs / has clients / has a strategy record / has a risk record / has
   a hearing scheduled), not a risk/health score. Overlapping category *names* (documents, deadlines) but
   a different question ("is setup complete" vs. "how much risk exists"). Not a duplicate.

3. **`services/case_pipeline.py` risk snapshot step (line ~526) and next-action step (line ~584)** — both
   confirmed to correctly call `services.risk_engine.calculate_procesni_rizik` /
   `identify_case_problems`. The next-action step's own docstring documents that it replaced a THIRD
   independent GPT-based "next action" implementation on 2026-07-22 (Core Consolidation) — already fixed,
   not a new finding.

4. **`api.py` (Cockpit endpoint, ~line 4961)** — explicitly computes `_deterministic_risk` via
   `calculate_procesni_rizik` and passes it into the GPT prompt as ungrounded-in-guesswork context
   ("vec izracunat, ne menjaj" — already calculated, do not alter). Correct delegation, not a violation.

5. **`services/confidence_calibrator.py:184`** — reads `nedostajuci_dokazi` from a passed-in `kontekst`
   dict (produced upstream by Risk Engine), does not recompute it. Consumer, not a second owner.

6. **Case Genome ("snaga_predmeta_procent") consumers** — checked every non-Genome file that references
   `snaga_predmeta`/`case_strength`: `routers/health_index.py`, `routers/cio.py`,
   `routers/case_intelligence.py`, `routers/multi_agent.py`, `routers/intelligence_timeline.py`,
   `routers/strategy_simulator.py`. All six read `genome.get("snaga_predmeta_procent")` (or the
   `predmet_genome_history` table populated by Genome writes) — none independently compute a case-strength
   number. This confirms Project Synapse's Copilot/Firm Brain fix pattern has NOT been contradicted
   elsewhere; these six were already correct.

7. **Audit/history writes** (`predmet_istorija` inserts from `routers/matter_intel.py`, `api.py`,
   `shared/deps.py`, `services/case_pipeline.py`, `routers/rocista.py`) and the separate `audit_log` table
   (written only by `shared/audit.py`'s `AuditMiddleware`) — these are two different tables serving two
   different purposes (`predmet_istorija` = domain case-timeline entries; `audit_log` = generic
   HTTP-request security audit trail, single writer). Multiple modules appending distinct timeline
   entries to a shared history table is normal (like independent log lines), not a "two sources of truth
   for one fact" violation — no module recomputes another's *entry*, they each append their own kind of
   event. **Worth noting as a Low-severity observation, not a violation**: there is no shared
   `write_case_history_entry()` helper — each site hand-builds its own insert dict. This is a schema-drift
   risk (an easy place for a future field to be misspelled or omitted inconsistently) but is not in scope
   for Phase 4 (source-of-truth duplication) — it's a Phase-1/consistency hygiene item, not a
   multiple-owner problem.

8. **`routers/court_predictor.py:986` (`_calc_confidence_nivo`)** and other `_compute_*`/`calculate_*`
   function definitions found by the broad grep (`security/chain_anchor.py`, `routers/case_dna.py`'s
   `_compute_delta`, `shared/audit_immutable.py`'s `_compute_entry_hash`, `routers/product_intelligence.py`,
   `routers/smart_intake.py`) — each checked and confirmed to compute a distinct, module-local concept
   (hash chaining, genome diffing, analytics session bucketing, job-wait-time estimation, judge-prediction
   confidence) with no overlap with Risk Engine, Genome, or Strategy Engine's owned facts/conclusions.

## Conclusion

**One new HIGH-severity finding survives this broader sweep**: `routers/dashboard.py`'s
`matter_health_score` endpoint — a third, differently-weighted, currently-orphaned case-health formula
that contradicts the canonical `calculate_procesni_rizik` and is fully alive (routed + tested) rather than
inert dead code. Every other candidate surfaced by the grep sweep was verified by reading the actual
implementation and ruled out as either a correct delegation to the canonical source, a distinct concept
answering a different question, or a normal multi-writer append pattern to a shared history table (noted
as a Low-severity hygiene item, not a violation). No fixes implemented — this file is the read-only
Phase 4 deliverable per directive.
