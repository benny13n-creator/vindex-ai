# Technical Design - Word Add-in Task 01: Secure Authentication

**Author (role):** Solution Architect
**Date:** 2026-11-01
**Product Specification:** 2026-11-01_word-addin-task01-auth_PRODUCT_SPECIFICATION.md
**Status:** Red Team FREEZE READY; Security CONDITIONAL; Database Architect lifecycle condition confirmed; migration numbering held for PR #66

## Existing-Functionality Check

The main client uses existing Supabase Auth and bundles its JS at `static/supabase.min.js`. The Word prototype persists a pasted bearer. `api.py` has its own verifier; `shared/deps.py` also verifies tokens and can fall back to local validation after provider errors. Neither helper enforces the full Word exchange contract as-is. Before route dispatch, `api.py::user_rate_limit_middleware` calls `verify_token_local` for every API request with a Bearer header. The global security-header middleware sets `X-Frame-Options: SAMEORIGIN` and CSP `frame-ancestors 'none'` on all responses. The global `/api/logout` affects all user sessions. No Word session registry exists.

## Design

1. **Dialog sign-in and legacy-token cleanup.** Use a same-origin Office dialog with existing Vindex/Supabase identity. Configure the SDK with persistSession false and detectSessionInUrl false. Return only its short-lived access JWT through Office dialog messaging; never put credentials in a URL, Word document, roaming setting, persistent browser storage, or log. Before showing auth state, clear legacy key vindex_auth_token from both Office roaming settings and localStorage without reading or reusing it; await roaming saveAsync completion and fail closed with an error if cleanup is not confirmed.
2. **Dedicated verifier and rate-limit boundary.** POST /api/word/sessions uses a Word-specific verifier; do not call api.py::_verify_token, shared.deps::_verify_token, shared.deps::verify_token_local, or their FastAPI dependencies unchanged. Directly require provider get_user(token) success, then validate signature with the configured Supabase signing key, allow-listed algorithm and exact kid; require exact issuer, audience authenticated, nonempty subject, and present/valid/future numeric exp. JWT subject must match provider-confirmed user ID. Provider rejection/outage or any claim uncertainty fails closed; no fallback and no client-supplied identity/expiry. In user_rate_limit_middleware, carve out only paths under the exact /api/word/ segment before the Bearer-token parsing branch; skip only that parser and continue through call_next, so SlowAPI default and route-specific IP limits remain active. The namespace must contain only Word routes, and every protected route must require the opaque Word session. Before issuing a session, after source identity is verified, apply the existing general API user-rate bucket using the provider-confirmed user ID. After opaque-session validation, apply a Word post-auth rate guard before side effects: session management and future non-AI Word routes use the existing general API user bucket; analysis and rewrite use the existing AI user bucket and run _anomaly_record plus _anomaly_check before analyzer/provider work. Map route operation classes explicitly; do not classify the entire Word namespace as AI or trust client-supplied user/session IDs. Keep account-wide buckets shared across sessions and IPs for each server-verified user. The existing in-memory limiter guarantees this only within one worker; gunicorn defaults to one worker, but WEB_CONCURRENCY overrides and replica count are unknown. Before a controlled pilot, prove single-worker operation or obtain an approved shared account counter; do not change deployment settings here. All non-Word routes retain current middleware behavior. Word-specific failure logging records reason/correlation only and never token text/prefix; do not log provider exception bodies.
3. **Opaque session.** On exchange, create a cryptographically random opaque token, store only its SHA-256 hash plus provider-derived user ID and timestamps, and return it once. Expiry is `min(verified source exp, now + 3600 seconds)`; reject expired/unknown expiry. Database errors deny issuance. Keep the raw Word token in pane memory only.
4. **Callback binding.** Bind each dialog to a one-time random nonce held in pane memory. Check `Office.context.requirements.isSetSupported("DialogOrigin", "1.1")` before opening the dialog. Compare complete expected origin (scheme, host, port), nonce, message type, and schema. Missing/mismatched origin yields no session. Hosts without verifiable origin fail closed.
5. **Word-only authorization.** A Word dependency checks token hash, expiry, revocation, and DB availability per request and returns server-derived identity. Word routes call existing `PermissionService.require(feature)` with that identity; do not edit `shared/permissions.py` or duplicate entitlement logic. Normal bearer-authenticated web routes remain unchanged; reuse the existing analysis/retrieval components.
6. **Logout and provider dispatch.** `DELETE /api/word/sessions/current` revokes only the current Word row. Logout immediately clears pane state/results, increments a session generation, aborts every fetch, stops watchers, and suppresses callbacks from older generations. For every outbound provider attempt in a Word operation (embeddings, completion, optional reranking, and each application retry), run a conditional atomic claim against the live Word session immediately before the provider call. Revocation committed first means that attempt is not dispatched; a claim committed first authorizes only that attempt, which may finish remotely. Disable hidden SDK retries for Word provider clients; retries must be application-controlled and claim again. Revocation errors are non-retryable. Recheck before returning results and suppress them server- and client-side after logout. Already-dispatched work cannot be recalled. Report unconfirmed remote revocation. Never call global `/api/logout`.
7. **CSP and framing.** On Word HTML entry responses under /word_addin/*, set one effective Word-specific CSP that replaces (does not append to) the global CSP; keep current global policy unchanged for unrelated routes. Remove X-Frame-Options only on Word entry responses. Preserve same-origin and Supabase connect-src; allow the Office.js source actually used and only verified Word-host origins in frame-ancestors. Word script-src must not include unsafe-inline or unsafe-eval; move taskpane and commands JavaScript into same-origin files or use a per-response nonce/hash with verified host behavior. Establish host origins from official Microsoft guidance and actual host evidence, not assumed broad wildcards. Inspect response chains/proxy/root responses too; if a host is blocked upstream, mark it unsupported until a safe isolated policy is available. Verify taskpane, commands, and auth-dialog headers, Office.js, dialog messaging, and Supabase auth on each claimed host.
8. **Registry migration.** The reviewed contract is one public.word_sessions table with a UUID ID, server-derived auth.users user ID under a named ON DELETE RESTRICT foreign key, a unique lowercase SHA-256 token hash, created/expires/revoked/last-dispatch-claim timestamps, expiry checks (after creation and no later than one hour), user/expiry indexes, RLS without anon/authenticated policies, and explicit server-only service_role grants. Generate at least 32 random bytes; return the opaque token once and store only its hash. Retain revoked rows through their original expiry; expired rows are cleanup-eligible then. Add cleanup to the existing daily retention job, surfacing failures; successful runs give a nominal 24-hour maximum physical retention after expiry. The current routers/gdpr.py account endpoint soft-anonymizes profile data, so revoke all Word sessions before reporting erasure success and fail closed if revocation fails; hard Auth deletion must delete session rows first. Use plain CREATE TABLE, never IF NOT EXISTS. The Database Architect confirmed this exact retention/erasure contract on 2026-11-02. Do not name or author the Word migration while PR #66 is open/Draft and reserves migration 146. Resolve PR #66, synchronize this branch with canonical main, and verify the next unused slot. If 146 merges, use 147 only after checking competing assignments and apply/verify 146 before 147; if PR #66 closes unmerged, explicitly release or reassign 146 rather than assuming it is free. No migration is executed.
9. **Audit.** Use registered immutable audit actions for sign-in, failure, and logout with channel, reason, correlation ID, and non-secret session row ID. No passwords, tokens, prefixes, or fragments.
10. **Cost boundary.** Use deterministic provider mocks only. PR #66 is open/Draft; do not call live AI or claim paid execution is financially protected.

## Patterns Reused

Existing Supabase identity, `PermissionService`, `UsageService`, immutable audit actions, `/word_addin` mount, bundled Supabase JS, Office.js dialogs, and current Vindex retrieval/analyzer. Do not change main web login or global logout.

## Database Impact

One Word-session registry supports per-pane revocation and atomic attempt claims. Revoked rows remain until their original expiry; expired rows are eligible for deletion by the existing daily retention job, with failures surfaced. The GDPR soft-erasure route must revoke all Word sessions before success and fail closed; a future hard Auth deletion removes Word rows first, with ON DELETE RESTRICT as the database guard. Database Architect confirmed this contract on 2026-11-02. Migration 146 belongs to open PR #66; do not name or author the Word migration until that PR is resolved, this branch is synchronized with canonical main, and the next unused slot is verified. No production migration will run.

## Security-Relevant Surface

Provider-token signature/claim validation, session issue/revoke, rate-limit middleware carveout, callback origin, effective CSP/X-Frame-Options, in-memory secrets, every external dispatch/retry, audit, and Word API routes. Trust Blueprint capabilities 1, 2, 9, and 10. Task 01 sends no document text.

## Alternatives

Reject manual/persistent tokens, global logout, missing-origin fallback, shared verifier fallback, editing `shared/permissions.py`, duplicated entitlements, request-level claims for every retry, and Microsoft identity.
